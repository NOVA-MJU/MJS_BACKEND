# 공지 의미 라벨링 가이드 v1

## 1. 공통 원칙

1. 제목에서 공지의 주제가 명확하면 제목을 우선한다.
2. 본문은 제목이 포괄적이거나 대상·캠퍼스·마감 근거가 필요할 때 확인한다.
3. 본문에서 다른 제도, 자격 요건, 관련 링크가 단순 언급됐다는 이유만으로 Topic을 추가하지 않는다.
4. Topic과 Audience를 섞지 않는다. `신입생 대상 도서관 행사`는 신입학 공지가 아니다.
5. `[]`는 미지정이고 `ALL`은 전체라고 명시된 경우에만 사용한다.
6. 직접 Topic만 `directTopicIds`에 기록하고 부모는 `expandedTopicIds`에 추가한다.
7. 사용자 구독이나 알림 발송 가능성은 정답 라벨에 반영하지 않는다.

## 2. Topic

### 포함 기준

- 제목 또는 공지의 핵심 행동이 해당 Topic의 정의와 직접 연결된다.
- 한 공지에 독립적으로 중요한 주제가 둘 이상이면 복수 라벨을 허용한다.
- 하위 Topic이 명확하면 부모 Topic만 직접 부여하지 않는다.

### 제외 기준

- 대상 설명에만 Topic 단어가 등장한다.
- 관련 규정·참고 링크·과거 공지를 인용한다.
- 작성 부서명에만 `취업`, `장학`, `학생` 같은 단어가 들어간다.
- 제목의 한 글자나 우연한 문자열 경계만 일치한다.

### 대표 경계

| 표현 | 정답 |
|---|---|
| 졸업사정 결과 조회 | `GRADUATION_REQUIREMENTS` |
| 학사학위 취득유예 신청 | `GRADUATION_DEFERRAL` |
| 졸업연주회 | `GRADUATION_ART_EVENT` |
| 졸업생 대상 취업컨설팅 | `GRADUATE_CAREER` |
| 해외취업 설명회 대상에 졸업생 포함 | 졸업 Topic을 자동 추가하지 않음 |
| 신입생 대상 도서관 행사 | `NEW_TRANSFER_ADMISSION` 아님, Audience만 `NEW_STUDENT` |
| 신·편입학 당해학기 군휴학 | `LEAVE_RETURN`, Audience는 신입생·편입생 |

### 제목만으로 부족한 경우

- 제목이 `프로그램 안내`, `추가 안내`, `결과 안내`처럼 주제를 생략한 경우
- 제목의 기관명·사업명만으로 실제 목적을 알 수 없는 경우
- 여러 절차가 한 공지에 묶인 초과학기 학사 안내
- 외부 기관 장학·기숙사·취업 사업처럼 카테고리와 핵심 혜택이 다른 경우

이 경우 본문의 첫 목적 문장과 신청 대상 문장을 근거로 표시한다. 첨부 링크나 하단의 관련 공지 목록은
근거로 사용하지 않는다.

## 3. Event Type

우선순위는 문장 내 단어 순서가 아니라 공지의 핵심 행위로 결정한다.

| 라벨 | 포함 기준 | 제외·경계 |
|---|---|---|
| `APPLICATION` | 신청·접수 절차와 기간 안내 | 참가자를 경쟁 선발하는 모집은 `RECRUITMENT` |
| `RECRUITMENT` | 참가자·장학생·직원 모집 또는 선발 | 선발 결과는 `RESULT` |
| `CHANGE` | 일정·방법·정책의 변경 또는 정정 | 단순 최신 안내는 `INFORMATION` |
| `ADDITION` | 추가 신청·추가 모집·추가 선발 | 기간만 늘면 `EXTENSION` |
| `EXTENSION` | 기존 마감의 연장 | 지연 안내는 현재 Catalog에서 `INFORMATION` 후 gap 기록 |
| `RESULT` | 합격·선발·심사 결과 | 결과 제출 요청은 핵심 목적을 재검토 |
| `CANCELLATION` | 신청·행사·수업의 취소·철회 | 제도 폐지는 Topic과 함께 판단 |
| `SUSPENSION` | 서비스·운영의 중단·중지 | 일시적인 지연은 별도 gap 후보 |
| `INFORMATION` | 일정·제도·운영 일반 안내 | 신청 행동이 핵심이면 `APPLICATION` |
| `UNKNOWN` | 근거 부족 | 빈 제목 또는 해석 불가에만 제한적으로 사용 |

## 4. Audience

- 문서가 직접 호명한 대상만 기록한다.
- `졸업예정자`, `졸업생`은 각각 별도 라벨이다.
- `수료생`, `휴학생`, `대학원생`, `교직원`, 특정 학년은 현재 enum에 없으므로 억지로 기존 값에 넣지 않고
  `reviewNotes`에 Catalog gap으로 기록한다.
- `재학생 및 졸업생`처럼 복수 대상이면 모두 기록한다.

## 5. Campus

- `인문캠퍼스`/`서울캠퍼스`는 `SEOUL`, `자연캠퍼스`/`용인캠퍼스`는 `YONGIN`이다.
- 양쪽이 각각 열거되면 두 값을 모두 기록한다.
- `양 캠퍼스`, `전체 캠퍼스`라고 명시된 경우만 `ALL`을 쓴다.
- 작성 부서 주소나 페이지 하단 연락처는 적용 캠퍼스 근거가 아니다.

## 6. Deadline

- 신청·접수·제출의 마지막 시각만 기록한다.
- 게시일, 행사일, 결과 발표일, 서비스 중단 종료일을 마감일로 사용하지 않는다.
- 여러 독립 마감이 있으면 대표값을 임의 선택하지 않고 `deadline=null`로 두고 검수 메모를 남긴다.
- 날짜만 있고 시간이 없으면 해당 학교 운영 기준을 별도로 확인한다. v1 정답에서는 추측하지 않는다.
- 기존 `valid_until`은 후보값일 뿐 정답이 아니다.

## 7. Evidence와 검수

- 모든 양성 라벨은 제목 또는 본문의 정확한 근거 구간을 하나 이상 가진다.
- 음성 사례는 `reviewNotes`에 왜 유사 Topic을 부여하지 않았는지 기록한다.
- 자동 초안은 `AUTO_DRAFT`, 사람이 확인하면 `REVIEWED`, 의견 조정까지 거치면 `ADJUDICATED`다.
- 라벨러가 다르면 Topic 정의와 공지의 핵심 행동 문장을 우선한다. 해결되지 않으면 기존 Topic에 억지로 넣지 않고
  Catalog gap으로 승격한다.

## 8. 복수 라벨 결정 순서

1. 제목에서 독립된 행동이 둘 이상인가?
2. 각 행동이 없어도 공지의 목적이 유지되는가?
3. 한 표현이 단순 대상·자격·관련 링크인가?
4. 하위 Topic으로 충분히 설명되는가?

1과 2가 참이고 3이 아니면 복수 라벨을 허용한다. 부모 Topic은 직접 라벨에 넣지 않는다.
